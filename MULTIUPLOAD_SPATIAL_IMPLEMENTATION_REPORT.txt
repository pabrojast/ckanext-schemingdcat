2) Objetivo funcional (lo que se implementó)
-------------------------------------------

A) Multiupload:
   Permitir subir/crear múltiples recursos (resources) a partir de múltiples
   ficheros seleccionados en una sola interacción.

B) Detección/Extracción espacial:
   Cuando se suben archivos geoespaciales compatibles (p.ej. SHP, GeoTIFF,
   GeoJSON, KML, GPKG y ZIP con Shapefile), se calcula la extensión espacial
   (bounding box) y se devuelve/guarda como GeoJSON.

   Además, se intenta detectar “member states” (países) solapados/contenedores
   del extent y usar esa detección para:
   - autocompletar `spatial_uri` (dataset)
   - añadir grupos (dataset) relacionados con esos países
   - opcionalmente actualizar/combinar el `spatial` del dataset

4) Flujo A: Multiupload “simple” (selección múltiple en el input de upload)
---------------------------------------------------------------------------

Archivo: `ckanext/schemingdcat/assets/js/modules/schemingdcat-multi-resource-upload.js`

Cómo funciona:
  1) Al inicializar, fuerza `multiple` en inputs file que matchean:
       input[type="file"][id^="field-resource-upload"]
  2) Captura el evento `change` del input.
  3) Si el usuario selecciona >1 fichero:
       - deja el primer fichero en el resource actual
       - por cada fichero adicional:
           - simula click en el botón “Añadir recurso”
           - espera ~250ms a que CKAN clone el bloque
           - asigna el fichero al input del nuevo bloque (DataTransfer)
           - auto-rellena campos básicos (name/format/created)

Dónde se inyecta:
  - `ckanext/schemingdcat/templates/schemingdcat/package/snippets/resource_form.html`
  - `ckanext/schemingdcat/templates/schemingdcat/package/snippets/package_form.html`

Notas/limitaciones:
  - Depende de selectores DOM específicos (id `field-resource-upload*`,
    `.add-resource` / `#add-resource`, etc.). Si el snippet de upload cambia
    (p.ej. el upload “moderno” usa un input con id `upload`), este módulo puede
    no interceptar el input esperado.
  - Requiere `DataTransfer` para setear `input.files` de forma programática;
    navegadores muy antiguos pueden no soportarlo.


5) Flujo B: Batch upload (widget dedicado que crea N resources vía API)
-----------------------------------------------------------------------

Archivos:
  - UI snippet: `ckanext/schemingdcat/templates/schemingdcat/snippets/batch_upload.html`
  - Lógica: `ckanext/schemingdcat/assets/js/modules/schemingdcat-batch-upload.js`
  - Toggle/habilitación: `ckanext/schemingdcat/templates/schemingdcat/package/snippets/resource_form.html`

Cómo funciona (alto nivel):
  1) Permite seleccionar múltiples ficheros (input multiple + dropzone).
  2) Por cada fichero arma un “fileItem” con estado/progreso.
  3) Si `useDirectUpload` y Azure está disponible:
       - POST `/api/get-azure-upload-url` -> SAS URL + blob_path
       - PUT directo a Azure Blob (xhr)
       - POST `/api/3/action/resource_create` (JSON) con:
           - `url` apuntando al blob (sin SAS)
           - flags `azure_upload` + `azure_blob_path`
  4) Si no hay Azure:
       - POST `/api/3/action/resource_create` (multipart/form-data)
         subiendo `upload` + metadatos.
  5) Al finalizar, redirige a `/dataset/<packageId>` si todo OK.

Extracción espacial en batch (frontend):
  - Para extensiones: shp/geojson/kml/gpkg/tif/tiff/zip
  - Hace POST con FormData(file) a un endpoint de extracción y guarda:
      - `metadata.spatial` = GeoJSON extent
      - `metadata.spatial_uri` si se detecta país
  - Luego incluye `metadata` en el `resource_create`.

Observación importante:
  - El endpoint usado en el JS es `'/schemingdcat/api/extract-spatial-extent'`
    mientras que el Blueprint del plugin expone `'/api/extract-spatial-extent'`
    (sin prefijo). Si en este despliegue no existe un prefijo de ruta, la
    extracción espacial del batch puede no estar llamando al endpoint correcto.
  - Además, el batch guarda el extent en la clave `spatial` (resourceData),
    pero el schema de recursos (p.ej. UNESCO) usa `spatial_extent`. Si el schema
    no define `spatial` como campo de resource, ese valor podría quedar como
    extra no utilizado o ignorarse en UI.


6) Detección/Extracción espacial (detalles técnicos)
----------------------------------------------------

6.1 Endpoint: `/api/extract-spatial-extent` (frontend -> backend)

Archivos:
  - Ruta: `ckanext/schemingdcat/blueprint.py`
  - Handler: `ckanext/schemingdcat/upload/api.py` -> `extract_spatial_extent_endpoint()`

Entradas soportadas:
  A) multipart/form-data con `file`
  B) JSON con `resource_url` y `resource_format` (para procesar por URL)

Salida:
  - `extent`: GeoJSON (Polygon/MultiPolygon/GeometryCollection según casos)
  - `spatial_uri`: mejor país detectado (o null)
  - `spatial_uris`: lista de países solapados (o vacía)

6.2 Extracción del extent (bbox -> GeoJSON)

Archivo: `ckanext/schemingdcat/upload/extractors.py`
Clase: `SpatialExtentExtractor`

Formatos soportados (por extensión):
  - shp (vector): Fiona
  - zip (zip shapefile): Fiona + extracción a tmp dir
  - tif/tiff/geotiff (raster): Rasterio
  - kml/gpkg/geojson/json (vector): Fiona

Normalización CRS:
  - Vector (Fiona): intenta reproyectar bounds a EPSG:4326 si CRS != 4326
  - Raster (Rasterio): usa `transform_bounds` hacia EPSG:4326 si aplica

Representación:
  - El bbox se convierte a GeoJSON Polygon (5 puntos cerrando el anillo).

6.3 Detección de “member states” (países) desde extent

Archivo: `ckanext/schemingdcat/upload/extractors.py`
Clase: `MemberStateDetector`

Fuente de países:
  - Lee el schema del dataset y toma los `choices` del campo `spatial_uri`.
  - Cada choice puede incluir un atributo `spatial` (GeoJSON) con el polígono
    del país; se reduce a bounds para calcular solapes.

Algoritmo (resumen):
  - Extrae bounds del extent.
  - Para cada país (bounds):
      - si el extent está totalmente contenido, prioriza esos matches
      - si hay solape, calcula % de solape (sobre el área del extent)
  - Devuelve:
      - `detect_member_state`: mejor match (contenido o mayor solape >= threshold)
      - `detect_member_states`: lista ordenada (contenidos primero, luego solape)

Helpers asociados:
  - `ckanext/schemingdcat/helpers.py`:
      - `schemingdcat_detect_member_state(s)`
      - resolución de grupo para un country URI:
        `schemingdcat_find_member_state_group()` / `schemingdcat_get_member_state_group_slug()`


7) Extracción “post-creación” (job backend) y autocompletado de dataset
----------------------------------------------------------------------

Disparo del job:
  - `ckanext/schemingdcat/plugin.py` (SchemingDCATDatasetsPlugin)
    - `before_create`: marca `_needs_metadata_extraction` si:
        - es upload (`url_type == 'upload'` o `resource.get('upload')`)
        - o si `_should_extract_metadata()` lo considera candidato por format/url
    - `after_create`: llama `_trigger_metadata_extraction(resource)`
    - chained actions: también llaman `_trigger_metadata_extraction` para
      asegurar ejecución aunque hooks no se disparen.

Ejecución:
  - Por defecto usa fallback vía threading:
      `self._fallback_metadata_extraction(resource)` -> `extract_comprehensive_metadata_job`
    Motivación indicada en código: issues de ejecución de RQ en CKAN 2.10.

Job:
  - `ckanext/schemingdcat/jobs.py` -> `extract_comprehensive_metadata_job(job_data)`
  - Descarga el fichero a un temp file (soporta:
      - URL pública
      - URL segura de cloudstorage (SAS) o descarga autenticada por API key)
  - Ejecuta análisis con `FileAnalyzer`:
      `ckanext/schemingdcat/upload/analyzers.py`
  - Parcha el resource con `resource_patch` (`ignore_auth=True` en contexto)
  - Si hay `spatial_extent`, detecta países y llama:
      `_add_member_states_to_package(package_id, detected_uris, ..., spatial_extent=extent)`
    que hace `package_patch` para añadir grupos / spatial_uri / spatial

Auto-fill de dataset (config):
  - En `_add_member_states_to_package` se lee:
      `schemingdcat.spatial.auto_fill_dataset` (default True)
  - Si está habilitado, puede actualizar:
      - `spatial` (GeoJSON) combinando con el valor existente
      - `spatial_uri` (elige/actualiza el URI)

Merge de geometrías:
  - `ckanext/schemingdcat/jobs.py` -> `_merge_geojson_geometries()`
    intenta consolidar extents múltiples en MultiPolygon o GeometryCollection.

9) Dependencias y degradación
----------------------------

Dependencias opcionales (extras “spatial”):
  - fiona, rasterio, pyproj, GDAL (ver `spatial-requirements.txt` y `setup.py`)

Comportamiento sin dependencias:
  - La extracción espacial devuelve None / falla silenciosamente en frontend
  - El job de metadata intenta extraer lo posible y sigue sin bloquear el flujo


10) Puntos a revisar (inconsistencias detectadas)
-------------------------------------------------

1) Endpoint en batch upload:
   - `schemingdcat-batch-upload.js` llama `'/schemingdcat/api/extract-spatial-extent'`
   - El Blueprint registra `'/api/extract-spatial-extent'`
   => Si no hay un prefijo real, la detección espacial en batch no funcionará.

2) Campo donde se guarda el extent en batch upload:
   - batch guarda `resourceData.spatial` (no `spatial_extent`)
   - los schemas revisados usan `spatial_extent` para recursos
   => Puede quedar en un campo no mostrado/no usado.

3) Multi-resource upload vs upload moderno:
   - multi-resource upload busca inputs con id `field-resource-upload*`
   - el upload moderno define un input `id="upload"` (en `form_snippets/upload.html`)
   => El multi-upload “simple” puede no aplicarse al widget moderno salvo que
      haya otro input compatible en el DOM (p.ej. por cloudstorage).


11) Recomendación de validación manual (pasos)
----------------------------------------------

1) Crear dataset y abrir “Add data” (resource/new).
2) Probar batch upload (si está habilitado) y/o selección múltiple:
   - seleccionar 2+ ficheros y confirmar que se crean N recursos.
3) Subir un fichero geoespacial (GeoJSON/TIF/SHP/ZIP shapefile):
   - comprobar que se rellena `spatial_extent` (frontend o post-job).
4) Revisar dataset:
   - `spatial` y `spatial_uri` (si auto-fill habilitado)
   - grupos de países añadidos (si hay correspondencias en schema/grupos)
5) Revisar logs del servidor para confirmación del job:
   - logs del plugin y de `extract_comprehensive_metadata_job`.
