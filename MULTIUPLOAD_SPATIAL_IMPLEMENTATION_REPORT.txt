Scope
-----
- Multi-upload: create multiple resources from one selection.
- Spatial extraction: derive extent + country from geo files, autofill resource/dataset fields.

Frontend touchpoints
--------------------
- Simple multi-select splitter: `ckanext/schemingdcat/assets/js/modules/schemingdcat-multi-resource-upload.js`; injected in package/resource form snippets. Forces `multiple` on file inputs, clones resource blocks, assigns extra files, auto-fills name/format/created. Depends on selectors `field-resource-upload*`, `.add-resource`.
- Batch upload widget: `assets/js/modules/schemingdcat-batch-upload.js` + `templates/schemingdcat/snippets/batch_upload.html`; enabled via `ckanext.schemingdcat.batch_upload_enabled` (default true). Supports dropzone, per-file status, Azure direct upload (`/api/get-azure-upload-url`) or multipart `resource_create`. Performs client-side spatial extraction before calling the API.
- Modern upload preset: `templates/schemingdcat/form_snippets/upload.html` + `upload_snippets/upload_script.html`; modular scripts `upload_ui.html` (dropzone/progress) and `upload_spatial.html` (calls extraction endpoint) used by preset field `resource_url_upload`.

Backend touchpoints
-------------------
- Blueprint routes: `ckanext/schemingdcat/blueprint.py`
  - POST `/api/extract-spatial-extent`
  - POST `/api/extract-spatial-extent-from-resource`
  - POST `/api/get-azure-upload-url`
- API handler: `ckanext/schemingdcat/upload/api.py`; accepts multipart `file` or JSON `{resource_url, resource_format}`, returns `extent` GeoJSON + `spatial_uri`/`spatial_uris`.
- Extractors: `ckanext/schemingdcat/upload/extractors.py`
  - `SpatialExtentExtractor`: supports shp/zip-shp, geojson/json, kml, gpkg (Fiona) + tif/tiff/geotiff (Rasterio); reprojects to EPSG:4326; outputs GeoJSON polygon from bbox.
  - `MemberStateDetector`: reads `spatial_uri` choices from schema, compares extent bounds vs country bounds, prefers containment then overlap to pick best URI/list.
- File analyzer: `ckanext/schemingdcat/upload/analyzers.py` (`FileAnalyzer`) gathers metadata for jobs.
- Hooks and chained actions: `ckanext/schemingdcat/plugin.py` (`SchemingDCATDatasetsPlugin`)
  - `before_create` flags `_needs_metadata_extraction`.
  - `after_create` and chained `resource_create/resource_update` trigger extraction.
- Job runner: `ckanext/schemingdcat/jobs.py` (`extract_comprehensive_metadata_job`)
  - Downloads the file (direct URL, cloudstorage SAS, or API-auth download).
  - Runs `FileAnalyzer`; `resource_patch` writes metadata incl. `spatial_extent`.
  - Uses `MemberStateDetector` to add package groups, `spatial_uri`, and merge dataset `spatial` when `schemingdcat.spatial.auto_fill_dataset` (default true).

Flows and behavior
------------------
- Simple multiupload: multi-select on legacy upload input; clones resource rows for extra files. Not active if the upload widget uses a different input id.
- Batch upload:
  - For Azure: get SAS via `/api/get-azure-upload-url`, PUT to Blob, then `resource_create` with `url`, `azure_upload`, `azure_blob_path`.
  - Fallback: multipart `resource_create` per file.
  - Client-side spatial extraction for extensions shp/geojson/kml/gpkg/tif/tiff/zip; metadata attached to create payload.
- Modern upload: dropzone triggers backend extraction, fills resource fields, and shows progress; shares extraction logic with API.

Known gaps / risks
------------------
1) Endpoint prefix mismatch: batch JS calls `'/schemingdcat/api/extract-spatial-extent'` but Blueprint exposes `'/api/extract-spatial-extent'`. Without a real `/schemingdcat` prefix, batch spatial extraction fails.
2) Field name mismatch: batch stores extent in `resourceData.spatial`; reviewed schemas use `spatial_extent` for resources, so the extent may be ignored.
3) Selector dependency: simple multiupload watches `field-resource-upload*`; modern upload uses `id="upload"`, so the multi-select splitter may not run there.
4) Optional deps: requires fiona/rasterio/pyproj/GDAL (see `spatial-requirements.txt`). Without them, extraction silently degrades.

Quick validation steps
----------------------
- Enable batch upload, select multiple files, confirm it creates one resource per file and redirects.
- Upload geospatial files (GeoJSON/TIF/SHP/zip-shp) through batch or modern upload; check resource `spatial_extent`.
- Inspect dataset after upload: `spatial`, `spatial_uri`, and country groups added when auto-fill is enabled.
- Review logs from `extract_comprehensive_metadata_job` for extraction failures or country detection output.
